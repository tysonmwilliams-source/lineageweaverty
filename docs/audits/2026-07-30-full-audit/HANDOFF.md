## Working rules for this repo

- **`docs/claude-context/*.json` are the owner's files.** They are the app's
  exported world state, regenerated by the running app via the dev-only
  `POST /__claude-context` endpoint. Read them; never edit, never commit them,
  and never include them in a staged change. They are untracked as of `705583f`
  (decision F6) but still present locally.
- **Stage with explicit paths. Never `git add -A` or `git add .`** — the working
  tree routinely carries the owner's context exports and stray `.DS_Store`s, and
  a blanket add sweeps them into your commit.
- **This repository is PUBLIC.** Confirmed via `gh repo view`. It matters more
  than it looks: the leaked Gemini key in history has been scrapeable, the world
  data in past commits is readable by anyone, and this audit itself catalogues
  every weakness in the app. The owner chose to leave history as-is (decision A2)
  after being told.
- **The owner works in batches and has authorised pushing straight to `main`.**
  The established rhythm: implement, verify, commit with a message that explains
  *why the bug existed*, fast-forward `main`, push. Confirm before doing anything
  irreversible that wasn't explicitly asked for (a remote branch deletion needed a
  direct yes; a history rewrite would too).
- **Present open decisions as pickable choices, not prose.** Use
  `AskUserQuestion` with 3–4 options per question, a recommendation marked in the
  first option, and a `preview` showing the concrete trade — effort, risk, and
  what you give up. This is what the owner asked for and it has moved far more
  decisions than describing them did. Batch up to 4 at a time; use `multiSelect`
  for independent housekeeping items.

## Two lessons that changed how the audit should be read

- **A scanner count is not a defect count.** "28 stylesheets have zero media
  queries" turned out to be 8 theme files with no layout at all, and of the rest
  only 3 actually broke. "1,175 console calls", "239 emoji", "17 tabs" (really 15)
  are the same shape of number. Measure what breaks before acting on a count, and
  say so when the count was misleading.
- **The audit is good and it is wrong in specific, load-bearing places** — roughly
  one claim in ten. Several would have caused damage implemented as written. Always
  re-verify a claim before building on it; correct the audit file when it's wrong
  rather than quietly working around it. Full list under "Where the audit was
  wrong" below.

## Where the audit was wrong

Corrections found while implementing, recorded so nobody re-derives them. The
audit files themselves have been annotated.

**Phase 3**

- **Part One #35 was wrong.** Do NOT import `src/styles/shared/` or
  `shared-forms.css`. Those 112 class names are used **zero** times in JSX;
  `buttons.css` uses `.lw-*`, `shared-forms.css` uses `.form-*` — two
  incompatible, unadopted drafts. Importing ships dead CSS and risks restyling
  two forms. Folded into B1/B3.
- **The dataset-switch bug was latent, not live** — both switch paths call
  `window.location.reload()`. The provider is keyed defensively anyway.
- "The design system was built and never turned on" was too generous. It was
  drafted twice and neither draft was adopted. The fix is a decision, not wiring.

**Phase 4**

- **`.DS_Store` was already in `.gitignore`.** Only `src/features/` needed
  deleting.
- **`arcMilestones` was worse than a phantom.** Both upload paths read
  `localDb.arcMilestones.toArray()` as the last of seven planner reads inside one
  `try`, so every upload threw a `TypeError` and logged "Could not get planning
  data". The six real tables were already assigned, so no data was lost — but a
  working sync looked broken.
- **`formatDate` had ten definitions, not three.** Four were the same relative-
  time formatter; the `CodexBrowse` copy had drifted so its fallback dropped the
  year entirely. Two more in `PersonList` were identity functions.
- **`@keyframes spin` was 21, not 22** — and in two different spellings.
- **SVGO needs `mergePaths` disabled too**, which the audit did not flag. It
  collapsed 133 paths into 8 on one charge; rewriting subpaths into a single `d`
  can flip even-odd/nonzero winding and quietly alter traced art with no source
  to regenerate from. Costs 1.9pp of savings. Result: 20.19 MB → 10.01 MB with
  all 12,243 white fills preserved exactly.
- **Do not drop `@types/react*`.** The handoff said to; decision F4 recommends
  keeping them for `// @ts-check` + JSDoc. Left in place.
- **A live `ReferenceError` was introduced by Phase 1** and caught here: moving
  `validateProposal()` inside a `try` scoped `const validation` to that block,
  while the success return at `aiProposalExecutor.js:172` still read
  `validation.warnings`. Every successful AI proposal execution threw.

**Phase 5**

- **`downloadHeraldry()` did not exist.** The audit called it dead code; there
  was no export path at all. Written from scratch as
  `src/utils/downloadHeraldry.js`.
- **`runIntegrityCheck()` could not have caught the broken Crown.**
  `findOrphanedRecords` checked relationships→people, people→houses and
  codexLinks→entries. Nothing looked at dignities. Extended with dignity and
  heraldry checks before wiring, plus 7 tests.
- **`targetWordCount` was already rendered for beats** (`BeatSheetView`). The
  unrendered one was the per-*writing* target, which is what got the progress
  ring.
- **`reorderChapters`/`moveChapter` had no sync.** Wiring them as-is would have
  meant every reorder silently reverting on the next cloud download. Both now
  take a trailing `userId`.
- **`validateWikiLinks`/`getSuggestedEntries` called `getAllEntries()` with no
  `datasetId`** — latent only because they had no callers. Threaded before use;
  otherwise a non-default world validates against the default database and every
  link reports as broken.
- **`[[` autocomplete already existed in the TipTap editor** via
  `entitySearchService`. The gap was the Codex entry form.

**Phase 6** — none of these were in the audit at all; they were found by
re-checking the work rather than by reading the report.

- **47 `<Icon name="...">` call sites across 18 files rendered nothing.** `Icon`
  returns `null` for a name missing from `LUCIDE_ICONS` and only warns in DEV, so
  the whole class was invisible in production: `loader-2` on four loading
  spinners, `grip-vertical` on the planner's drag handles, `hourglass` on
  interregnum markers, `circle`/`square` status pips, `log-out` in the user menu.
  27 icons added (map: 207 → 234 names). `src/test/icon-map.test.jsx` now scans
  every `.jsx` and asserts each name renders an `<svg>`, so it can't recur.
  **If you add an `<Icon name>` and the icon doesn't appear, this is why —
  check the map, not the component.**
- **`parseWikiLinks` silently dropped a third argument.**
  `CodexEntryView.jsx:183` was already passing `datasetId` to a two-parameter
  function. Every entry in a non-default world resolved its links against the
  *default* database, and the links it auto-creates were written there too — the
  phantom-database class Phase 0 was meant to have closed.
- **Two CSS rules stopped matching when emoji became `<Icon>`.**
  `.generating-indicator span` and `.preview-placeholder span` sized an emoji by
  `font-size`; `Icon` renders an `<svg class="lw-icon">`, so the Armory's spinner
  stopped spinning and the placeholder shield shrank to 20px. **General lesson:
  when replacing an emoji with `<Icon>`, grep the stylesheet for a `span`
  selector sizing it — an SVG inherits neither `font-size` nor that selector.**

## CLAUDE.md — fixed in Phase 4

All six documented errors are corrected in `cbcbeec`, so CLAUDE.md can now be
trusted on these points. Recorded here only so the corrections aren't re-derived:
7 themes not 2; the console count (now moot — everything routes through
`src/utils/logger.js`); `contextRegistry`/`contextFiles`/`contextLog` *are*
written (`contextService.js:711/744/768`) but never sync; README.md is accurate
and the warning about it was the stale part; `seatName` is a *dignity* field, not
a house field; and the feature flags are **unimplemented**, not "intentionally
off" — 3 of 40 are read, all already `true`, all in `PersonForm.jsx`.

Three conventions were added to CLAUDE.md at the same time, and they are load-
bearing:

- **Logging:** import `logger` from `src/utils/logger.js`; never call `console.*`
  directly. `log`/`warn`/`info`/`debug`/`group`/`table` are DEV-only no-ops,
  `error` always reports.
- **Shared keyframes** live in `src/styles/animations.css` (loaded in
  `main.jsx`). `@keyframes` are global in CSS — don't redeclare a name a
  component stylesheet already owns.
- **Adding a Dexie version:** declare only the changed store. Dexie inherits the
  rest. Restating all 26 tables is how the `dateOfDeath` index went missing in
  v3/v4. Schema is at **v18**.

Also: `addHouse(data, options)` takes an options object while
`addPerson(data, datasetId)` takes a string. Genuine inconsistency, easy to get
wrong. And planner mutations — plus `updatePerson`/`updateHouse`/`updateEntry`
and the chapter reorder functions, as of Phases 4–5 — take a trailing `userId`
and sync. Don't add one without it.

## Working conventions used so far

- One commit per phase. Commit messages explain *why the bug existed*, not just
  what changed.
- Verify build + tests + lint before each commit; report the deltas honestly,
  including when a number goes the wrong way.
- **Add tests for anything whose failure mode is silent.** Phases 0–6 took the
  suite from 148 to 425. Two real bugs were found *by writing the test*, not by
  reading the code — the backwards caret span in `findLinkSpanAtCaret` and the
  `validation` ReferenceError.
- **Re-verify the audit's claims before acting on them.** It is a good document
  and it is wrong in specific, load-bearing places — see "Where the audit was
  wrong" above. Roughly one claim in ten needed correcting, and several would
  have caused damage if implemented as written (importing dead CSS, SVGO breaking
  every charge recolor, dropping `@types` against decision F4).
- When a fix reveals the audit was wrong, say so plainly and correct the audit
  file rather than quietly working around it.
